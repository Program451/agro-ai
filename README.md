# EginQanat AI

Фронтенд на PHP работает на хостинге, Python API и исходная модель `best.onnx` — на вашем ноутбуке. Дизайн создан в Google Stitch и адаптирован в работающий интерфейс без внешних библиотек оформления.

Проект Stitch: https://stitch.withgoogle.com/projects/3900699482078060482

Панель ESP32 показывает температуру, влажность воздуха, давление, высоту и датчик дождя. Датчика почвы нет: прежнее поле soil_raw игнорируется и не передаётся в совместный анализ. Пошаговое подключение находится в `ESP32-OBS.txt`, пример ESP32 — в `esp32/agroai_example/`. В OBS можно переключать уже подключённые к нему источники и сцены; EginQanat AI анализирует итоговое изображение виртуальной камеры.

## Быстрый запуск на этом компьютере

После установки зависимостей откройте `start-local.bat`, затем http://127.0.0.1:8080. Он запускает Python и PHP. `stop-local.bat` останавливает только запущенные этим проектом службы. Для работы сайта с хостинга используйте `start-hosting.bat`, который запускает Python и временный HTTPS-туннель.

В репозитории нет `.env`, приватного `config.local.php`, виртуального окружения и записей пользователей. Настройки создаются командой `setup.py`; библиотеки устанавливаются из `requirements.txt`. Модель `best.onnx` включена в репозиторий.

## Установка на другом компьютере

Нужен Python 3.10+ (проверено на 3.12). Для локального просмотра также нужен PHP 8.1+ с расширением cURL. Для бэкенда, обслуживающего сайт на хостинге, PHP на ноутбуке не требуется.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe setup.py
.\.venv\Scripts\python.exe server.py
```

`setup.py` создаёт случайный ключ в `.env` и соответствующую настройку в `frontend/config.local.php`. Существующий ключ не заменяется. Держите эти файлы приватными. Для локального PHP можно указать путь к программе в переменной `AGRO_PHP_BIN` или добавить PHP в PATH и выполнить `python launch.py`.

Для просмотра обработанного видео в браузере установите FFmpeg и добавьте его в PATH (или задайте `FFMPEG_BIN` в `.env`). Без него анализ выполнится, но результат будет доступен для скачивания в MPEG-4, который поддерживают не все браузеры. В обработанном видео нет звука.

## Размещение PHP на хостинге

Требования к хостингу:

- PHP 8.1 или новее, расширение cURL.
- HTTPS для сайта и исходящие HTTPS-запросы с хостинга.
- Возможность загрузки файлов; лимиты `upload_max_filesize`, `post_max_size` и веб-сервера определяют максимальный размер видео.
- Для дрона — поддержка долгих потоковых PHP-ответов. Фото и асинхронная обработка видео не требуют долгого соединения на время анализа.

1. Выполните установку и `setup.py` из раздела выше.
2. Скачайте Windows-версию `cloudflared` по инструкции Cloudflare ниже и сохраните как `tools/cloudflared.exe`. Эта сторонняя программа не включена в Git. Скрипт не скачивает её автоматически.
3. Запустите `start-hosting.bat`. После сообщения «Подключение ноутбука готово» скопируйте созданный `run/hosting/config.local.php` в `frontend/config.local.php` **на хостинге**. Держите окно запуска открытым. Подробности: [HOSTING-CONNECTION.txt](HOSTING-CONNECTION.txt).
4. При первом размещении загрузите **содержимое только папки `frontend`** в каталог сайта, например `agro-ai/frontend/`, вместе с настройкой из шага 3. Python-код, модель, `.env` и папку `run` на PHP-хостинг загружать не нужно.
5. Откройте сайт. Индикатор «Модель подключена» означает, что PHP смог связаться с вашим ноутбуком.

Если вы запускаете постоянный туннель самостоятельно, можно создать конфигурацию командой:

```powershell
python setup.py --backend-url https://YOUR-TUNNEL-HOST
```

В этом случае на хостинг загружается созданный `frontend/config.local.php`.

Если используется отдельный архив фронтенда, скопируйте `config.example.php` в `config.local.php`. Впишите HTTPS-адрес бэкенда и значение `AGRO_API_TOKEN` из `.env` на ноутбуке. Один и тот же ключ хранится только в серверных настройках двух сторон. Он не выводится в HTML или JavaScript.

Домен сайта может быть любым: браузер обращается к `api.php` на том же домене, а PHP — к ноутбуку. Настраивать CORS для каждого домена не требуется. `localhost` в настройках хостинга обозначает сам хостинг, поэтому для ноутбука там нужен адрес туннеля.

`.user.ini` содержит рекомендуемые параметры PHP, но хостинг может их ограничивать. `.htaccess` закрывает прямой доступ к конфигурации на Apache. На Nginx дополнительно запретите HTTP-доступ к `config*.php`, скрытым файлам и листингу каталогов. PHP-конфигурацию нельзя раздавать как статический текст.

## HTTPS-туннель к ноутбуку

Для проверки можно использовать Cloudflare Quick Tunnel:

```powershell
cloudflared tunnel --url http://127.0.0.1:8000
```

Утилита выводит временный HTTPS-адрес. Укажите его в `config.local.php` на хостинге. После нового запуска адрес может измениться. Для постоянного сайта используйте постоянный Cloudflare Tunnel со своим доменом или другой HTTPS-туннель с постоянным адресом.

Установка и актуальные условия: https://developers.cloudflare.com/tunnel/get-started/
Временные туннели: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

В репозитории нет адреса действующего туннеля и ключей. Для новой установки подключение настраивается заново. Все соединения с Python API требуют ключ. Режим сетевой камеры выключен по умолчанию. Туннель публикует только порт Python API.

Ноутбук должен оставаться включённым, с интернетом, работающими Python и туннелем. Если он уснул или отключён, сайт остаётся доступным, но анализ недоступен. Ограничения туннеля и хостинга могут быть ниже лимита приложения; начинайте с коротких видео.

## Возможности

- Фото: JPG, PNG, WebP до 20 МБ и 40 мегапикселей, рамки объектов, уверенность, скачивание JPG и JSON.
- Видео: до 200 МБ на уровне приложения, первые 60 секунд по умолчанию, около 5 анализируемых кадров в секунду, шкала активности и скачивание результата. Максимум API — 120 секунд. Задачи выполняются в очереди на ноутбуке; интерфейс проверяет готовность короткими запросами.
- Камера: кадры из браузера, последовательные запросы без накопления, остановка камеры при смене раздела.
- OBS: выберите OBS Virtual Camera в разделе «Камера / OBS» и переключайте источники внутри OBS. Сайт нужно открыть на том же устройстве, где работает OBS. Телефон и дрон предварительно подключаются к OBS согласно возможностям этих устройств.
- ESP32: температура, влажность воздуха, давление, высота, сырые показания дождя. Обновление каждые 5 секунд, отметка устаревших данных через 120 секунд, сохранение последних 10 000 пакетов в SQLite. До подключения показания не подставляются.
- Датчики на хостинге: чтение существующего `data.csv` и показания даже при выключенном ноутбуке. Python получает ту же историю через `sensor-feed.php` для Gemini. Файлы существующей метеостанции сохранены в `hosting-station/`; схема размещения — в [HOSTED-SENSORS.txt](HOSTED-SENSORS.txt).
- 22 исходных класса: 17 категорий вредителей и 5 состояний поля. Названия в интерфейсе переведены на русский.
- Gemini сопоставляет кадр, показания одного ESP32 и изменения за последние 30 минут. Разовый анализ фото/кадра записи или AI-наблюдение камеры: новый запрос через 30 секунд после ответа, сеанс до 30 минут. В отчёте — наблюдения, условные риски на 24–48 часов, советы и ограничения. Подключение: `GEMINI_API_KEY` в `.env`, модель — `GEMINI_MODEL`. Пошаговая инструкция: `GEMINI.txt`.
- Журнал сохраняет до 500 отдельных кадров с отчётами и использованными показаниями в `data/insights.sqlite3`. Интерфейс показывает последние 50; можно открыть кадр и скачать JSON. Полное видео записывается в OBS отдельно.

На сайте три вкладки: «Фото», «Видео» и «Камера / OBS». Телефон и дрон выбираются как источники в OBS. Просмотр камеры использует пропорции 16:9, ширину до 640 пикселей и уменьшается вместе с экраном. Если источник занимает только часть сцены OBS, выберите его и используйте «Преобразовать → Подогнать по размеру экрана» (Ctrl+F).

Кнопка «Начать анализ» запускает локальную модель. Кнопка «Начать общий анализ» анализирует одно фото или выбранный кадр файла; для подключённой камеры она запускает повторяющиеся AI-наблюдения. Датчик выбирается автоматически. Отдельные поля культуры, участка и ID, а также прежние кнопки AI-наблюдения убраны.

Порог обнаружения закреплён в PHP-шлюзе на 35% для фото, видео и камеры. Ползунка в интерфейсе нет; переданный посетителем порог не применяется. Нижние счётчики классов, пошаговые подсказки и раздел «Как это работает» убраны. Каталог классов также убран из интерфейса; подписи объектов в результатах анализа сохранены.

## Хранение и точность

Фото и кадры обрабатываются в памяти приложения; PHP может временно сохранять загрузку в системной папке хостинга. Видео временно сохраняется на ноутбуке в `_tmp`; входные файлы удаляются после обработки. Готовые файлы старше суток удаляются при запуске или следующей загрузке видео. Очередь задач хранится в памяти: после перезапуска бэкенда незавершённую задачу нужно отправить заново.

Фото и видео проходят через ваш хостинг и провайдера туннеля. По нажатию «Начать общий анализ» Gemini получает JPEG-кадр, доступные показания и историю одного ESP32, а также предположения YOLO. В режиме наблюдения запросы повторяются до остановки, скрытия вкладки или завершения 30 минут. Уже отправленный запрос может завершиться после остановки. Ключ хранится только в `.env` на ноутбуке, исключён из Git; браузер его не получает. `.env` не шифрует данные. На публичном хостинге доступ посетителей к AI-функциям следует ограничить средствами хостинга, если сайт личный.

Показания выбираются по времени получения сервером до момента кадра. Для CSV с хостинга сохраняется исходное время записи (Asia/Almaty, UTC+5), повторное чтение не делает его свежим. Задержка ESP32 неизвестна; часы браузера и серверов должны совпадать. Для старых фото/видео текущие показания явно отмечаются как контекст другого времени. Без свежих данных, калибровки или достаточной истории прогноз ограничен. Сырые ADC дождя не переводятся в проценты. Gemini оценивает условные риски, а не предсказывает погоду или урожайность. Отчёты AI могут ошибаться.

Отсутствие обнаружений не доказывает, что поле здорово. Оценка уверенности — результат модели, а не измеренная точность или агрономический диагноз. Для видео счётчики означают обнаружения по кадрам, а не количество уникальных насекомых. Исходная модель сохранена без изменения; метаданные модели указывают Ultralytics YOLO11n и AGPL-3.0.

## Структура

```text
frontend/           PHP-сайт: только эту папку загружают на хостинг
  index.php         разметка интерфейса
  api.php           шлюз к ноутбуку с серверным ключом
  config.local.php  приватные настройки; создаются setup.py
  assets/           стили, JavaScript, иконка
backend/app.py      FastAPI, загрузка файлов, очередь видео, поток, рекомендации
backend/sensors.py  приём и хранение показаний ESP32
backend/insights.py Gemini: кадр + телеметрия, очередь и журнал наблюдений
esp32/              пример интеграции с существующим скетчем датчиков
hosting-station/    существующий приёмник ESP32 и отдельная страница метеостанции
engine.py           обработка ONNX и отрисовка объектов
best.onnx           исходная модель
server.py           запуск бэкенда
setup.py            создание настроек и смена адреса туннеля
connect-hosting.py  запуск Python и временного HTTPS-туннеля для хостинга
launch.py           локальный запуск двух служб
.env                приватные настройки ноутбука; создаются setup.py
run/                журналы локального запуска
data/               локальные базы ESP32 и AI-наблюдений, не входят в архив
```

## Проверка

```powershell
python -m pip install pytest httpx
python -m pytest tests -q
node --test tests/test_camera.cjs tests/test_watch.cjs tests/test_insight_controls.cjs
php tests/test_hosted_sensors.php
```

Тесты Python проверяют локальную модель, очередь видео, скачивание, авторизацию, телеметрию и совместный анализ. Запросы Gemini в тестах подменяются: реальная квота не расходуется. JavaScript-тесты проверяют камеры, единую AI-кнопку и остановку наблюдения. PHP-тест проверяет CSV датчиков, время, нули и устаревшие пакеты. История ручных проверок и ограничения находятся в [CHECKS.txt](CHECKS.txt).
